Stage package standard
======================

The GeoAquaCrop toolchain is three independently developed packages presented
through one façade. This page is the contract that makes that work: if every
stage follows it, ``import geoaquacrop`` gives a uniform API, and each package
still stands alone.

Naming
------

.. list-table::
   :header-rows: 1
   :widths: 18 27 27 28

   * - Stage
     - Repository
     - Distribution (PyPI)
     - Import package
   * - preprocess
     - ``geoaquacrop_preprocess``
     - ``geoaquacrop_preprocess``
     - ``geoaquacrop_preprocess``
   * - simulate
     - ``geoaquacrop_simulate``
     - ``geoaquacrop_simulate``
     - ``geoaquacrop_simulate``
   * - visualize
     - ``geoaquacrop_visualize``
     - ``geoaquacrop_visualize``
     - ``geoaquacrop_visualize``

The rule is one word, a verb, and **one spelling everywhere**:
``geoaquacrop_simulate`` is the repository, the distribution, and the import
package. The façade attribute drops the prefix (``gac.simulate``), which is the
only place the name is written differently.

Underscores rather than hyphens, because Python import names cannot contain a
hyphen (it would parse as subtraction) while distribution names accept either.
Choosing underscores means the same string works in ``pip install``, in
``import``, and as the repository name.

.. note::

   One thing outside our control: pip and PyPI apply :pep:`503` normalisation,
   which treats ``-``, ``_`` and ``.`` as equivalent. So ``pip show`` displays
   ``geoaquacrop-simulate`` and the PyPI project URL uses a hyphen, whichever
   form we declare. Both spellings always resolve to the same package, so this
   is a display convention rather than a second name -- but it does mean you
   will occasionally see the hyphenated form in tooling output.

Public API
----------

**Export the stage's public API from the package's** ``__init__.py``, with an
explicit ``__all__``. Module layout below that is an implementation detail and
can change freely.

Every stage exposes ``run()`` as its primary entry point:

.. list-table::
   :header-rows: 1
   :widths: 22 78

   * - Stage
     - Required exports
   * - preprocess
     - ``run()`` — prepare all datasets. Optionally ``weather()``, ``soil()``,
       ``crop_calendar()``, ``crop_area()`` to re-run one step.
   * - simulate
     - ``run(config)``, ``example_config()``, ``input_requirements()``,
       ``build_reference()``, ``correct()``, ``compare()``, ``load_results()``
   * - visualize
     - ``run()`` — start the dashboard. 

So this must work for every stage::

    import geoaquacrop_simulate as sim
    sim.run(config)

and the façade then mirrors it exactly::

    import geoaquacrop as gac
    gac.simulate.run(config)

Conventions
-----------

**Entry points take keyword arguments, not configuration objects.** A user
should be able to call a stage in one expression, with editor completion and
sensible defaults::

    gac.preprocess.run(domain_shape_path='region.geojson', start_year=2011, ...)
    gac.simulate.run(data_path='/data/region/processed', start_date='2011/01/01', ...)

Accept an optional ``config=`` dictionary as a first parameter for programmatic
use, with explicit keyword arguments overriding it, and never mutate a
dictionary the caller passed in. Where several arguments almost always take the
same value, offer a shorthand that fills them (``data_path`` fills the four
input paths in ``simulate``).

**Take arguments, don't read globals.** ``run()`` accepts its configuration as
a parameter. A function that ignores its caller and reads a module-level dict
cannot be scripted, tested or documented. Keep a module-level
``EXAMPLE_CONFIG`` as a *template*, and have the console script call
``run(EXAMPLE_CONFIG)``.

**Import lazily in** ``__init__.py``. Use PEP 562 ``__getattr__`` so that
importing the package does not pull in heavy or optional dependencies. Loading
``geoaquacrop`` should cost nothing until a stage is actually used.

**Version from metadata**, so it cannot drift from ``pyproject.toml``::

    try:
        from importlib.metadata import version as _version
        __version__ = _version("geoaquacrop_simulate")
    except Exception:
        __version__ = "0.0.0.dev0"

**Console script** named after the distribution:
``geoaquacrop_simulate = "geoaquacrop_simulate.<module>:main"``.

**Optional dependencies as extras**, not hard requirements, so a user who only
wants one stage does not install the others' dependencies.

**Documentation**: Sphinx + Furo, sources in ``docs/``, built on ReadTheDocs
from a ``.readthedocs.yaml`` at the repository root, with an ``api/`` section
generated by ``autodoc``.
